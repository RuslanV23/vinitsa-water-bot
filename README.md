# Бот об отключениях воды в Винице: запуск с нуля

Бот читает **официальный сайт ВиК Варна**, находит объявления с упоминанием **Виницы** и присылает их в ваш личный Telegram. Он проверяет аварии и плановые ремонты **каждые 20 минут через GitHub Actions**. После настройки ваш компьютер можно выключить.

Ниже — весь путь по порядку. Платный сервер, домен и банковская карта для описанной схемы не нужны. Используйте **публичный репозиторий** и оставьте стандартный `ubuntu-latest` в workflow: такие запуски бесплатны по [условиям GitHub](https://docs.github.com/en/billing/concepts/product-billing/github-actions). Для приватного репозитория условия и лимиты другие.

## 1. Подготовьте программы и откройте папку проекта

Потребуются Telegram, бесплатный аккаунт на [github.com](https://github.com), Node.js **24 или новее**, Git и [GitHub Desktop](https://desktop.github.com/).

У вас Node.js уже установлен. Чтобы проверить версию:

1. Откройте папку проекта в Проводнике: `G:\телеграм бот воды`.
2. Щёлкните по адресной строке Проводника, напишите `powershell` и нажмите Enter.
3. В появившемся окне выполните:

```powershell
node --version
git --version
```

Первая команда должна показать `v24...` или более новую версию. Если версия ниже — установите актуальную LTS с [nodejs.org](https://nodejs.org/). Если Git не найден — установите его с [git-scm.com](https://git-scm.com/downloads/win). После установки заново откройте PowerShell.

Установите GitHub Desktop и войдите в нём в свой аккаунт GitHub: **File → Options → Accounts → Sign in**.

Все команды ниже вводите **в PowerShell, открытом в папке проекта**, по одной строке. Если окно открыто в другом месте, сначала выполните:

```powershell
Set-Location -LiteralPath 'G:\телеграм бот воды'
```

Здесь используется `npm.cmd`: на Windows обычная команда `npm` иногда блокируется политикой PowerShell. Менять политику безопасности не требуется.

## 2. Создайте своего бота в Telegram

1. Откройте официальный [@BotFather](https://t.me/BotFather).
2. Нажмите **Start / Запустить**, затем отправьте `/newbot`.
3. На запрос имени введите, например, `Вода Виница`.
4. На запрос username придумайте уникальное имя латиницей, заканчивающееся на `bot`, например `VinitsaWaterYourNameBot`. Если занято — выберите другое.
5. BotFather пришлёт **токен** — длинную строку с двоеточием. Скопируйте её целиком.

Токен — ключ управления ботом. Его нужно вставить в локальный помощник и GitHub Secrets на следующих шагах. Не помещайте токен в исходники, переписку, скриншоты или описание репозитория.

Для этого проекта создайте **нового отдельного бота**: подключение того же токена к другим сервисам может мешать настройке.

## 3. Установите зависимости и определите ID своего чата

В PowerShell в папке проекта выполните:

```powershell
npm.cmd ci
npm.cmd run setup
```

Первая команда устанавливает библиотеку для чтения HTML. Вторая запускает помощник настройки:

1. Вставьте токен из BotFather в окно PowerShell и нажмите Enter. Во время ввода токен виден на экране — не показывайте это окно другим.
2. Помощник покажет ссылку на вашего бота. Откройте её в Telegram.
3. Нажмите **Start / Запустить** или отправьте боту `/start`.
4. Вернитесь в PowerShell и нажмите Enter.
5. Появится список найденных личных чатов с именами и числовыми ID.
6. Введите **ID своего чата** из этого списка и нажмите Enter.

В Telegram должно прийти тестовое подтверждение. В папке проекта появится файл **`.env`**:

```dotenv
TELEGRAM_BOT_TOKEN=ваш_токен
TELEGRAM_CHAT_ID=ваш_числовой_ID
```

Это образец структуры: реальные значения помощник запишет сам. Сохраните файл на своём компьютере; на GitHub его загружать не нужно. Он уже исключён через `.gitignore`.

Если помощник пишет, что `/start` не найден, отправьте `/start` боту ещё раз и повторите `npm.cmd run setup`. Если `.env` уже создан, повторный помощник не перезапишет его: открыть и проверить настройки можно командой `notepad .env`.

**Обычные команды в Telegram пока не получают автоматических ответов.** Это бот уведомлений: он просыпается по расписанию на GitHub, проверяет сайт и отправляет объявления. `/start` нужен, чтобы разрешить ему писать вам.

## 4. Подготовьте файлы к загрузке на GitHub

В том же PowerShell выполните по одной строке:

```powershell
git init -b main
git config user.name "Water Bot"
git config user.email "water-bot@users.noreply.github.com"
git add .github src scripts test .gitignore .env.example package.json package-lock.json README.md
git commit -m "Add Vinitsa water alerts bot"
```

`Water Bot` — подпись локального сохранения кода, она не меняет ваш аккаунт GitHub. Команда `git add` перечисляет только файлы проекта: файл `.env` с токеном и папка `node_modules` в этот список не входят.

Проверьте:

```powershell
git ls-files
```

В списке должны быть `.github/workflows/water-check.yml`, исходники, инструкция и `package-lock.json`. **Файла `.env` в списке быть не должно.** Файл `.env.example` — пустой шаблон, его загружать можно.

## 5. Опубликуйте проект через GitHub Desktop

1. Откройте GitHub Desktop.
2. Выберите **File → Add local repository…**.
3. Нажмите **Choose…** и выберите `G:\телеграм бот воды`.
4. Нажмите **Add repository**.
5. Нажмите **Publish repository** в верхней части окна.
6. В поле **Name** введите `vinitsa-water-bot`.
7. **Снимите галочку `Keep this code private`**, чтобы репозиторий был публичным и стандартные запуски Actions оставались бесплатными.
8. Если есть выбор организации, оставьте свой личный аккаунт.
9. Нажмите **Publish repository**.
10. Откройте **Repository → View on GitHub**.

На сайте должны появиться папки `.github`, `src`, `scripts`, `test` и остальные файлы проекта. Если файлов нет, проверьте, что шаг 4 завершился успешным сохранением (`commit`).

Публичным будет **код и история обработки публичных объявлений**. Токен и ID чата дальше добавляются отдельно в Secrets.

## 6. Добавьте два секрета GitHub

Откройте **ваш репозиторий** в браузере, затем:

**Settings → Secrets and variables → Actions → Secrets → New repository secret**.

Создайте два секрета по очереди:

| Поле Name | Что вставить в поле Secret |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен от BotFather — значение справа от `=` в `.env` |
| `TELEGRAM_CHAT_ID` | Числовой ID вашего чата — значение справа от `=` в `.env` |

Для каждого нажмите **Add secret**. Значения вставляйте **без кавычек, без названия переменной и без знака `=`**. Чтобы прочитать локальный файл, выполните `notepad .env` в PowerShell.

После сохранения GitHub показывает названия секретов, но скрывает их значения. Это нормальное поведение. Если ошиблись, откройте редактирование секрета и задайте значение заново.

Этот путь соответствует [инструкции GitHub по Secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).

## 7. Проверьте разрешения GitHub Actions

В репозитории откройте **Settings → Actions → General**.

1. Убедитесь, что Actions разрешены и разрешены официальные действия **`actions/checkout`** и **`actions/setup-node`**. В личном новом репозитории настройки по умолчанию обычно подходят.
2. Найдите **Workflow permissions**.
3. Если доступен выбор, установите **Read and write permissions**, затем нажмите **Save**.

Право записи нужно для отдельной ветки **`bot-state`**, где бот хранит идентификаторы объявлений, даты и хеши текстов для защиты от повторов. Токен и ID чата туда не записываются. Код в основной ветке бот не меняет.

Создавать `bot-state` вручную не нужно. Не устанавливайте для этой служебной ветки правила, запрещающие боту прямую запись. Если используете аккаунт организации и запись запрещена её политикой, потребуется разрешение администратора либо личный репозиторий.

## 8. Запустите проверку отправки из GitHub

1. Перейдите во вкладку **Actions** вашего репозитория.
2. Если GitHub предлагает включить Actions, нажмите кнопку включения.
3. Слева выберите **Water alerts — Vinitsa**.
4. Нажмите **Run workflow**.
5. Выберите ветку **main**.
6. Поставьте галочку **«Отправить только тестовое сообщение (без проверки сайта)»**.
7. Нажмите зелёную **Run workflow** в открывшемся меню.
8. Подождите, пока появится запуск; если список пуст, обновите страницу.
9. Откройте запуск. При успехе появится зелёная галочка, а в Telegram — тестовое сообщение.

Это подтверждает, что **GitHub**, а не ваш компьютер, может отправлять сообщения. Тест не читает сайт и не меняет историю объявлений. Кнопки ручного запуска описаны в [документации GitHub](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow).

Если расписание успело запуститься до добавления Secrets и показало красный значок, после настройки просто выполните этот ручной тест ещё раз.

## 9. Запустите первое настоящее чтение сайта

Повторите **Actions → Water alerts — Vinitsa → Run workflow**:

1. Ветка — **main**.
2. Галочку тестового сообщения **снимите**.
3. Нажмите **Run workflow** и дождитесь результата. Обычно это занимает несколько минут вместе с ожиданием очереди.

При первом успешном запуске:

- придёт подтверждение, что мониторинг настроен;
- если найдены сегодняшние объявления о Винице, они придут отдельными сообщениями;
- старые объявления сохранятся без рассылки, чтобы не засыпать вас архивом;
- в репозитории автоматически появится ветка `bot-state`.

Первичная рассылка ориентируется на **дату публикации**, а не на разбор срока аварии. Поэтому при первом запуске проверьте сайт вручную на случай заранее опубликованного вчера предупреждения об отключении завтра. После запуска новые найденные объявления отправляются независимо от даты публикации.

**На этом настройка завершена.** Теперь GitHub запускает проверку автоматически в **:07, :27 и :47 каждого часа**. Например: 10:07 → 10:27 → 10:47 → 11:07. Смещение от начала часа уменьшает попадание в пиковую очередь; интервал остаётся 20 минут.

Закрывать PowerShell, GitHub Desktop и выключать компьютер можно. Не нужно запускать локальный бот параллельно: у локального запуска своя история, поэтому возможны повторные уведомления.

## 10. Как выглядит уведомление и что бот проверяет

Пример формата, **не настоящее текущее предупреждение**:

```text
🚰 Отключение воды — Виница
Опубликовано: ДД.ММ.ГГГГ
Без вода

От 9.00 до около 17.00 часа ... кв. Виница ...

Время в объявлении указано по Варне (Болгария).
Источник: https://vikvarna.com/...
```

Текст ВиК остаётся **на болгарском**, чтобы не искажать адреса и сроки. Платный переводчик и ИИ не используются. Если изменится текст или срок, придёт **«Обновление объявления о воде — Виница»**. Бот также сообщит об изменении ранее подходящего объявления, если в нём убрали упоминание Виницы.

Читаются полные тексты **30 последних объявлений в каждом из двух разделов**: [аварии](https://vikvarna.com/bg/messages/breakdown.html) и [плановые ремонты](https://vikvarna.com/bg/messages.html?region_id=0&sub_region_id=0&type=repair). Дополнительно ещё 14 дней с даты публикации проверяются уже известные объявления о Винице, даже если они ушли за первые три страницы. Если бот долго был выключен и за это время вышло больше 30 объявлений в разделе, часть пропущенного архива может оказаться вне охвата.

Фильтр ищет `Виница` и несколько вариантов написания. Он считает подходящим и сообщение с упоминанием насосной станции «Виница»: точную зону отключения смотрите в оригинале. Объявление, где перечислены только улицы без названия района, этот фильтр может пропустить. Отсутствие уведомления само по себе не подтверждает наличие воды.

## 11. Как убедиться, что всё продолжает работать

Откройте **Actions → Water alerts — Vinitsa** и посмотрите на последние запуски. Зелёная галочка означает, что чтение сайта и сохранение истории завершились успешно. Внутри запуска доступна сводка с количеством прочитанных и отправленных объявлений.

При отсутствии новых объявлений бот **молчит** — сообщение «всё в порядке» каждые 20 минут не отправляется. Проверить связь без изменения истории можно ручным запуском с тестовой галочкой из шага 8.

У GitHub есть два ограничения:

- Расписание выполняется без гарантии точного времени. Запуск может задержаться, а при высокой нагрузке — быть пропущен. Поэтому сообщение не гарантировано ровно через 20 минут после публикации.
- В публичном репозитории расписание отключается после **60 дней без активности репозитория**. Служебные запуски сами по себе не следует считать гарантией сохранения расписания. Раз в месяц проверяйте Actions и почту GitHub. Если workflow отключён, откройте **Actions → Water alerts — Vinitsa → Enable workflow**, затем выполните обычный ручной запуск без тестовой галочки.

Эти ограничения описаны в [документации расписания GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). Для включения и отключения есть [отдельная инструкция](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows).

## 12. Если возникла ошибка

Откройте **Actions → неудачный запуск → check** и разверните шаг с красным крестиком.

| Сообщение / ситуация | Что сделать |
| --- | --- |
| Не задан корректный `TELEGRAM_BOT_TOKEN` | Проверьте название и значение секрета из шага 6. Не вставляйте всю строку `TELEGRAM_BOT_TOKEN=...`. |
| Telegram: ошибка 401 | Скопируйте действующий токен из BotFather и обновите Secret. |
| Telegram: ошибка 400 | Проверьте `TELEGRAM_CHAT_ID` и отправьте `/start` именно вашему боту. ID — число, не username. |
| Telegram: ошибка 403 | Разблокируйте бота, откройте личный чат и отправьте `/start`. |
| Помощник настройки: ошибка 409 / webhook | Убедитесь, что токен не используется в другом приложении. Проще создать отдельного бота. |
| Не удалось загрузить ВиК / изменился формат страницы | Проверьте сайт в браузере. Временный сбой повторно проверится на следующем запуске. При изменении HTML потребуется обновить парсер в `src/source.js`. |
| Ошибка `Restore alert history` | Проверьте доступ к репозиторию и содержимое ветки `bot-state`. Повреждённую историю бот специально не сбрасывает автоматически. |
| Ошибка `Save alert history` | Проверьте права из шага 7 и защиту ветки `bot-state`. После такого сбоя часть сообщений может повториться: сайт проверен, но GitHub не сохранил новую историю. |
| Нет кнопки Run workflow | Убедитесь, что `.github/workflows/water-check.yml` есть в основной ветке `main`, Actions включены, а слева выбран нужный workflow. |
| Запуск серый / Skipped | Для ручного запуска выбирайте основную ветку `main`, не `bot-state`. |
| Давно нет запусков | Проверьте, не отключил ли GitHub расписание, и включите его по шагу 11. |
| `.env` не виден в Проводнике | Откройте его из PowerShell командой `notepad .env`. Не создавайте `.env.txt`. |

При частичной недоступности сайта бот обрабатывает доступные объявления и помечает запуск как неуспешный, чтобы сбой был заметен. После успешной отправки каждое объявление записывается в историю; workflow сохраняет эту историю и при последующей ошибке. Если процесс оборвётся между доставкой Telegram и записью истории, повтор сообщения всё же возможен.

Если токен случайно опубликован: в BotFather используйте `/revoke`, выберите бота и получите новый токен. Обновите его в GitHub Secret и локальном `.env`, затем отправьте тест. Простое удаление строки из последнего коммита не делает опубликованный токен снова секретным.

## 13. Дополнительные команды и управление

Команды для PowerShell в папке проекта:

| Команда | Что делает |
| --- | --- |
| `npm.cmd run setup` | Первый раз определяет чат и создаёт `.env`. |
| `npm.cmd run preview` | Читает настоящий сайт и показывает найденные упоминания. Telegram не используется, история не изменяется. Можно запускать без токена. |
| `npm.cmd run test-message` | Отправляет локальное тестовое сообщение, используя `.env`. |
| `npm.cmd test` | Проверяет парсер, уведомления, ошибки и сохранение ветки истории на локальном тестовом репозитории. Настоящие сообщения не отправляются. |
| `npm.cmd start` | Одна настоящая локальная проверка с отправкой сообщений. Это **не** запуск расписания. Для обычной работы используйте GitHub Actions. |

**Остановить мониторинг:** Actions → Water alerts — Vinitsa → меню **⋯ → Disable workflow**. Для возобновления — **Enable workflow**.

**Сменить получателя:** новый получатель сначала отправляет `/start` боту. Определите его числовой ID и замените `TELEGRAM_CHAT_ID` в GitHub Secrets. Уже обработанные объявления новому получателю повторно не рассылаются; проверьте связь тестовым запуском.

**Обновить код:** измените файлы локально, затем в GitHub Desktop выберите изменения, введите описание в Summary, нажмите **Commit to main → Push origin**. Историю `bot-state` удалять не нужно. Для обычной смены токена код обновлять не требуется — меняется только Secret.

В проекте нет постоянного сервера и нет веб-страницы: **GitHub Pages включать не нужно**. За регулярный запуск отвечает уже готовый файл `.github/workflows/water-check.yml`.
